# 子模板 · realtime-caption（实时渲染 + 图内双语）

> 把说明文字**画进正在运行的 3D 画面里**，而不是排在画面旁边的表格里。
> 同一张图两套文案（中 / 英），随时切；标注层是旁支产物，不污染截图基线。

## 它解决什么

一个实时渲染的 3D 作品，最难讲清楚的从来不是「好不好看」，而是**「看哪里」**。
写在正文里的解释和画面是分开的：读者读完文字要自己回图里找，找不到就放弃。
把解释钉在几何上，读者的眼睛不用在图文之间来回跳。

单语还不够。作品要给人看，中文读者和英文读者看到的是同一张图，
但**不是同一段解释**。图内双语的意思是：语言切换发生在图里，画面不动。

## 组成

| 文件 | 作用 |
|---|---|
| `caption.js` | 覆盖层运行时，零依赖，注入即用 |
| `labels.<project>.json` | 标注内容（锚点 + 双语文案） |
| `inject.py` | 把运行时 + 标注注入到一个已有单文件 HTML，产出第二份单文件 HTML |
| `SUBTEMPLATE.md` | 本文件：契约与自检清单 |

## 用法

```bash
python3 inject.py --in dist/scene.html \
                  --labels labels.myproject.json \
                  --out docs/labels.html
```

产物仍然是一个单文件 HTML：断网可开、双击即开。

## 标注契约

```json
{
  "id": "roof",
  "anchor": { "ref": "ROOF_CAP" },
  "offset": [0, 0.35, 0],
  "chip": [70, -60],
  "sub_zh": "屋顶", "sub_en": "ROOF",
  "zh": "压顶收边：把雨水甩离墙面",
  "en": "Roof cap: throws rain clear of the wall"
}
```

锚点四种写法，**优先级从高到低**：

| 写法 | 何时用 | 代价 |
|---|---|---|
| `ref: "NAME"` | 场景里有命名对象 | 最稳：几何动了标签跟着走 |
| `refPrefix: "P_"` | 名字带序号（`SPILL_POOL_0.00`） | 取第一个匹配，序号变了仍稳 |
| `world: [x,y,z]` | 场景里没有命名对象 | 逐帧投影，坐标是第二份真值 |
| `screen: [u,v]` | 兜底 | **别用**：相机一改就全歪，且不报错 |

`chip` 是标签框相对锚点的像素偏移，撞到画面边缘会自动翻到另一侧。
`sub_zh` / `sub_en` 是标签框上方的小标题（可省）。

## URL 协议

| 参数 | 值 | 说明 |
|---|---|---|
| `lang` | `zh` \| `en` | 图内语言 |
| `theme` | `night` \| `day` | 标注层配色（只管标注，不动画面本体） |
| `labels` | `0` \| `1` | 整层开关；截图流水线用 `0` 拿干净画面 |
| `capture` | `1` | 确定性截图模式；此时未显式指定 `labels` 则默认关闭标注层 |

## 三条硬约束

1. **锚点不许写死屏幕坐标。** 写死就是第二份真值：相机一改、机位一加，
   所有标签全歪，而且不报错。`inject.py` 会在构建期查锚点名字在不在产物里，
   查不到直接失败退出。
2. **标注层是旁支产物，不进主产物。** 主产物是确定性截图流水线的输入，
   多一个 UI 层就多一处污染。
3. **一切内联，不许外链。** 单文件 HTML 的价值是断网可开。外链一断标注层
   静默消失，页面照常显示，看起来「没问题」——这类失败最难查。

## 接入别人的场景要改什么

几乎不用改。运行时只依赖两样东西：

- `window.__SCENE_DIAGNOSTICS__.getScene()` / `.getCamera()`（有则优先）
- 否则退回全局 `scene` / `camera` / `THREE`

只要你的产物暴露这三者之一，注入即可。
