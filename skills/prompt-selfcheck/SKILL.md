# Prompt Selfcheck · 提示词文档四道闸门

## Overview

一份会被别人**照抄**的提示词文档，一旦开始多版本迭代，就会长出三类**不显眼但会误导读者**的失败：编号断裂、副本不同步、旧错复活。这三类错误人手数不出来（超过 ~40 条时手数必错），且**没有一道闸门是真的看得见**——它们只在读者按错的条款做完整套东西之后才暴露。

本 skill 提供一个零依赖脚本 `scripts/check_prompt.py`，把这三类失败加上一层"闸门自己有没有失效"的自测，变成**可复现的判决**（退出码 0/1/2），而不是"我 review 过了"。

## ⚠ 先读这一段：这套闸门不证明什么

**四道全绿 ≠ 文档正确。** 它只证明：编号连续、两份拷贝一致、**你列出过的**旧错没以断言形式复活、闸门自己在你测过的变异上会红。

它**不**证明：条款内容完整、语义等价、你没列出的错误不存在、排版美观。把绿当成发布许可，是这套工具最大的误用方式。

## 什么时候用（结构性条件，不是条款数量）

| 条件 | 为什么 |
|---|---|
| 文档有需要维护的条款编号或交叉引用 | 编号会静默断裂，"第 35 条"引用会指向不存在的东西 |
| 同一规范文本存在多份拷贝（文档 / 推文 / README / 精简版） | 改一处忘另一处，读者照那份做，得到的不是你说的东西 |
| 你维护着一份"已确认错误"清单 | 旧错最容易在**摘要表 / 推文 / 精简版**里复活——那是人注意力最先耗尽的地方 |
| 有发布前复制流程（推文、上传、部署） | 每个发布面都要单独跑一遍 regression |

> 不再以"超过 ~40 条"作门槛：五条条款也可能断号，一百条也可能稳。**看结构，不看长度。**

## 什么时候**不该**用

- 单版本、无副本、无编号的文档 —— 没有可检查的对象。
- 条款是普通 Markdown 列表 / 表格 / 层级编号（`1.1`、`1.1.1`）—— 解析器不认，会静默漏。**请先改成受支持的语法**（见下）。
- 需要检查"精简版是否忠实概括了完整版"—— `sync` 只查**同一内容的两份拷贝**是否一致，不查语义等价。要查忠实度，得人工或另建工具。
- 语言标签既非 `text` 也非白名单内、且你未意识到 —— 脚本会检查它并单独报告，但不会把它当提示词本体。

## 受支持的输入语法

**条款定义点（一律第 0 列，缩进的是子项）：**
- 圈码 `①` `㉑` `㊱`（覆盖到 50）
- 阿拉伯数字 `1. ` `1、` `1) ` `1 `（数字 + 标点或空白）

**提示词本体放 ```text 围栏块里**（否则编辑器会把它当散文改格式）。白名单语言标签：`text` / `plaintext` / `md` / `markdown` / 无标签。

**块选取优先级：** `--index` 显式指定 > 正文里的 `<!-- prompt:canonical -->` 标记 > 最长块（多块时打印警告）。

> 三条闸门必须作用在**同一个对象**上，否则"联合通过"没有共同主语。多块文档请显式指定索引或打 canonical 标记。

## Workflow

```
0. 跑 selftest         → 确认闸门自己没坏（19 项反证全绿）
1. numbering           → 条款 1..N 连续、节数相符
2. sync                → 两份拷贝一致
3. regression          → 旧错未以断言形式复活
4. 对每个发布面各跑一次 regression（文档 / 推文 / README）
5. 全绿才发布；任何一道红，先诊断再改
```

### Step 0 · selftest（先证明尺子没坏）

```bash
python3 scripts/check_prompt.py selftest
```

自动做 19 项反证：基线必须全绿、用法错误必须 rc=2、删条款必须红、`9 盏点光` 这种正文数字必须不误判、`1. ` 语法必须认、四种豁免绕过必须全抓住、python 块内的旧错必须抓住、断言折行必须抓住、正当订正必须不误报。**每次改完脚本必跑。**

### Step 1 · numbering

```bash
python3 scripts/check_prompt.py numbering prompt-v4.md --clauses 77 --sections 18 [--block 0]
```

- `--clauses N` 必填且 ≥1。脚本自动识别圈码与 `1. ` 系数字语法。
- 数字超过条款总数的行（`2026 年修订`）自动排除并明示。
- 单个杂散数字行（`9 盏点光从顶部投射。`）若剔除后编号恰好连续，判为正文并警告，不判失败。
- **圈码只到 50**。超过 50 条请改用阿拉伯数字；混排在实现上可行，但不推荐。

### Step 2 · sync

```bash
python3 scripts/check_prompt.py sync prompt-v4.md posts-v4.md --full-index 1 --short-index 0
```

- 比对的是**同一段内容的两份拷贝**。不是"完整规格 vs 精简提示词"——那样必然 FAIL，且是**正确的** FAIL。
- 归一化只忽略**行尾空白与首尾空行**，逐行保留前导缩进。不是"逐字节"，别那么理解。
- 精简版更长时打印警告——通常是索引选错了块。

### Step 3 · regression

```bash
python3 scripts/check_prompt.py regression prompt-v4.md \
    --bad "立面.{0,14}65\s*%" \
    --bad "端头挡住|被货架端头"
```

- `--bad` 是**正则**，描述错误的**断言形式**，可重复。不要用裸子串——`65%` 会在正当的"结构占 50–65%"上误报。
- **扫描三个面，合起来覆盖全文**：每个围栏块逐个查（含非 text 语言块）、去块后的正文、相邻行拼接补查（防断言折行）。
- **订正豁免**：命中行带订正标记时不算复活。标记默认用内置**多字**正则表。
  > ⚠ 单字 `错`/`编`/`别` **不能**作标记。`这个结论没错`、`与编号 ㉔ 一致`、`二者的区别在于`、`不能调整` 四个自然措辞都能把真复活豁免掉——已实证。
- **表格行按格判定**：一格断言旧错、另一格写"修正配色"，不整行豁免。
- 豁免的命中会**单独报告**（`△ N 处命中但判为订正引用`），不会伪装成"零命中"。
- `--fix-window N`：标记搜索窗口，默认 0 = 只算同一行。
- `--strict-blocks`：围栏块零容忍。仅在文档**不**把更正说明写进块内时使用。

## 引用旧错时的排版约定（显式告知，不再隐含）

判据默认"订正标记必须与旧错**同行**"。所以文档里引用自己的错误时，请写成：

```
原 v3 写「立面占 65%」，这是编的，已改为 ≤0.65 m。
```

**不要**把旧错和"这是错的"拆成两行——那会被判成复活（误报）。若必须折行，用 `--fix-window 1` 显式放款，并接受"放款可能放过真复活"的代价。

## 七条硬规则

1. **检查器报错 ≠ 文档通过。** 退出码 2 = 用法/文件/检查器错误，**按 FAIL 处理并修检查器**。`sys.exit(msg)` 会以 1 退出——本脚本因此专门改了退出码路径（案例九）。
2. **没红过的探针只是装饰。** 上线前必须反证。已固化为 `selftest` 一条命令；手工反证做法见 `gate-recipes.md`。
3. **订正窗口默认只算同一行。** ±4 行会让"专门讲自己错在哪"的文档把真复活也豁免掉（案例三）。
4. **条款定义点一律在第 0 列。** 缩进的圈码是条内子项。
5. **先诊断，不要为了变绿改文档。** 分清是文档错还是检查器错。实战里多次 FAIL 有超过一半是检查器误报。
6. **反证第一步是证明你确实制造了犯罪现场。** 先 `assert count==1` 并确认变异生效，再解读结果（案例五）。
7. **改脚本本身也要防回归。** 正则、豁免词表、块选取策略都是契约；每次改动后重跑 `selftest` + 对真实文档复跑三道闸门。

## 退出码

| 码 | 含义 | 动作 |
|---|---|---|
| 0 | 通过 | 进入下一步 |
| 1 | 检出问题 | 按报告修；先诊断是文档错还是检查器错 |
| 2 | 用法/文件/检查器错误 | **按 FAIL 处理**，修检查器或修命令，不要当成通过 |
