# 闸门反证做法

> **没红过的探针只是装饰。** 每个闸门上线前必须用"故意注入错误"证明它真的会红。
>
> **首选做法：`python3 scripts/check_prompt.py selftest`** —— 下面全部反证已固化为
> 一条命令，19 项，含基线必须全绿、用法错误必须 rc=2。本文保留手工版，
> 用于理解每个反证在测什么，以及在 selftest 之外自建变异时参考。

---

## 反证零 · 先证明尺子没坏

```bash
python3 scripts/check_prompt.py selftest      # 必须 19/19 + VERDICT: PASS
```

**为什么排在最前**：如果闸门本身是坏的，后面每个反证的结果都无法解释。
 selftest 同时锁定三类事——基线绿、变异红、**用法错误返回 2**。

---

## 反证一 · numbering（删一条条款）

```bash
# 从文档里删掉第 6 条定义那一行，然后：
python3 scripts/check_prompt.py numbering mutated.md --clauses 6 --sections 2
```

**预期**：`VERDICT: FAIL`，退出码 1，并打印

```
条款定义点：5 个（期望 6）
  ✗ 与 1..6 不符
    缺失：[6]
```

> ⚠ **曾在这里写错过**：旧版本文档写"删掉 ㊿（第 50 条）"却预期 `缺失：[77]`，
> 自相矛盾。删第 N 条就必须预期 `缺失：[N]`。已改为删第 6 条、预期 `[6]`。

**为什么这条能证明闸门有效**：它同时验证了计数、连续性、以及"缺失"的具体定位。
 只验证计数的话，一个把两条并成一条的变异也能让数字对上。

## 反证二 · numbering（正文数字不得误判）

```text
9 盏点光从顶部投射。
2026 年修订过一次。
```

混进条款之间，`--clauses` 不变。

**预期**：`VERDICT: PASS`，并打印

```
  ℹ 已排除 1 个越界数字行（数字 > 条款总数，判为正文）：L7:2026
  ℹ 已排除 1 个疑似正文数字行（剔除后编号恰好连续）：L5:9
```

**为什么重要**：这是 r20 评审实证的漏报面——旧版把 `9 盏点光` 和 `2026 年`
 吞成条款 9 和 2026，直接报 FAIL。修法是"越界即排除 + 剔除后能连续即判正文"。
 注意这个判据**不放过真缺号**：真删掉一条时，剔除任何单个候选都无法回到 1..N。

## 反证三 · numbering（阿拉伯数字语法）

```text
1. 第一条
2. 第二条
```

**预期**：`VERDICT: PASS`，`条款定义点：2 个`。

**为什么重要**：SKILL.md 曾承诺支持 `1. ` 而正则 `^(\d+)[\s\u3000]` 实际不认
 （数字后是 `.` 不是空白），报 `条款定义点：0 个`。这是 doc-vs-code 类型的缺陷。

---

## 反证四 · sync（改精简版一处）

```bash
# 在精简版里改一个数值，模拟"改了一处忘了另一处"
python3 scripts/check_prompt.py sync source.md mutated.md --full-index 1 --short-index 0
```

**预期**：`VERDICT: FAIL —— 两版不同步`，unified diff 精确指出那一行。

**前置**：`GOOD_POST` 必须是**同一段内容的拷贝**，不是另一段内容。
 曾用"只有一行的另一段文字"当基线，sync 报 FAIL 其实完全正确——是夹具错。

## 反证五 · regression（旧错改回断言句）

```bash
python3 scripts/check_prompt.py regression mutated.md --bad "立面.{0,14}65\s*%"
```

**预期**：`VERDICT: FAIL`，退出码 1。

**⚠ 做这条反证前必须先验证变异生效**：

```python
assert t.count(old) == 1
t2 = t.replace(old, new)
assert old not in t2          # ← 没有这一步，就可能把"文件没改"当成"检查器抓到"
```

## 反证六 · regression（四种豁免绕过必须全抓住）

```text
玻璃带占立面总高的 65%，这个结论没错。      ← 含单字「错」
与编号 ㉔ 一致：立面占 65% 高度。           ← 含单字「编」
二者的区别在于立面占 65% 高度。             ← 含单字「别」
立面占 65% 高度，不能调整。                 ← 含「不能」
```

**预期**：四条全部 `VERDICT: FAIL`。

**为什么重要**：旧版豁免词表含 `错/编/别/不能` 单字，这四条**全部 PASS**。
 它们是自然措辞，不是攻击——也就是说这个漏报在日常写作中就会触发。

## 反证七 · regression（两个扫描盲区）

```text
① 藏在非 text 围栏块里：
```python
x = "立面占 65% 高度"
```

② 断言被折行：
立面玻璃带占
总高的 65%。
```

**预期**：两者都 `VERDICT: FAIL`。

**为什么重要**：① 旧版 gate A 只查 text 块、gate B 又把所有块删掉，
 非 text 语言块两头都不查；② 逐行匹配天然跨不了行，而**编辑器自动折行就会造成它**。

## 反证八 · regression（正当订正不得误报）

```text
原 v3 写「立面占 65%」，这是编的，已改为 ≤0.65 m。
```

**预期**：`VERDICT: PASS`，并报告 `△ 1 处命中但判为订正引用`。

**关键**：订正标记必须与旧错**同行**。拆成两行会误报——这是已告知的排版约定，
 不是缺陷。确需折行时用 `--fix-window 1` 显式放款，并接受放过真复活的风险。

## 已踩的坑 · 精简版挑错块

**现象**：对同时含「完整设计规格」（24569 字符）和「精简提示词」（3452 字符）的文档跑
 `sync`，默认挑了最长的那块当"完整版"，于是拿**完整规格**比**精简提示词**，报一屏假 FAIL。

**根因**：默认启发式"最长的 text 块 = 完整版"在"文档里同时存在两种版本"时不成立。

**做法**：显式给索引，或用 canonical 标记。先列出所有块再决定：

```python
import re
BLOCK_RE = re.compile(r'```(\w*)\n(.*?)```', re.S)
bl = [(l, b) for l, b in BLOCK_RE.findall(t) if l in ('', 'text')]
for i, (l, b) in enumerate(bl):
    print(i, len(b), b.strip().split('\n')[0][:60])
```

**信号**：脚本打印 `⚠ 精简版比完整版还长` 时，先怀疑索引，不要怀疑文档。
