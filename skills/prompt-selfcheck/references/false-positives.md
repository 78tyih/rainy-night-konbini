# 误报 / 漏报档案

> 改 `check_prompt.py` 之前必读。这里记录三次"检查器说错话"的完整过程。
> 核心结论：**FAIL 不等于文档错**，先分清是文档错还是检查器错。

---

## 案例一 · 子项被当成条款（检查器错 → 修检查器）

**现象**：`numbering` 报 `条款定义点：79 个（期望 77）`，多出 2 个。

**现场**：新写的 ㊾ 里有这样的子项——

```
   ① 尺度      ② 分区      ③ 重复
```

以及一行以 `9 盏点光` 开头的正文。

**根因**：原判据是"行首出现圈码或数字就算条款定义点"。但**缩进的圈码是条内子项，不是条款**；以数字开头的普通正文行也被误吞。

**修的是什么**：检查器。条款定义点一律要求**在第 0 列**：

```python
ch = line[0]
if ch in CIRC: ...
elif ch.isdigit():
    m = re.match(r'^(\d+)[\s\u3000]', line)
```

**教训**：判据要描述**真实的语法**，不是"看起来像"。子项和条款在语义上完全不同，但在字符层面只差一个缩进。

## 案例二 · 引文被当成复活（检查器错 → 修检查器）

**现象**：`regression` 在一篇**刚刚修完错**的文档上报了 5 处"旧错复活"。

**现场**：v4 文档的 ⚠v4 更正说明里写着——

```
原 v3 写「**玻璃带占立面总高的 65%**」。**这个 65% 是错的，而且是编的。**
```

这正是文档**在讲自己错在哪**的句子。旧判据对可粘贴块做零容忍，于是把正常的自我订正判成复活。

**根因**：零容忍假设"文档不会引用自己的错误"。但一份认真记录错误教训的文档**必然**引用自己的错误——这是它的价值所在。

**修的是什么**：检查器。改为**订正上下文豁免**——命中行附近出现"错/编/推翻/修正/曾经/栽过/打回"等词时不算复活；同时提供 `--strict-blocks` 作为 opt-in 的零容忍模式，供"文档不把更正说明写进粘贴块"的场景使用。

**教训**：检查器的默认值要适配**文档的正常形态**，不是理想形态。把一个正当行为判成错误，比漏报更糟——它会训练人忽略检查器。

---

## 案例三 · 窗口太宽，真复活被豁免（检查器错 → 修检查器）

**现象**：反证实验里，把一条已修正的错误**改回断言句**，检查器仍报 `PASS`。

**现场**：原文是更正说明——

```
原 v3 写「**玻璃带占立面总高的 65%**」。**这个 65% 是错的，而且是编的。**
```

替换成——

```
「**玻璃带占立面总高的 65%**」是成立的。
```

**替换确实生效了**（先验证了"目标串出现 1 次"，排除了空替换 / 假通过）。但 ±4 行的窗口把邻近行的"错/编"词也算进来，豁免了这条**真正的复活**。

**根因**：豁免窗口的宽度与"文档有多喜欢讨论自己的错误"直接冲突。一篇以讲错为业的文档，几乎每一处旧错旁边都有这类词。

**修的是什么**：检查器。窗口默认从 ±4 行收紧为 **0（只算同一行）**，并把坑写进 `judge()` 的 docstring 和 `--help`。

**教训**：这是三个案例里最危险的一个——**它让检查器在真的该红的时候绿**。漏报比误报更难发现，因为没有任何信号提示你"这次没查"。

## 案例四 · 修完正文忘了摘要表（文档错 → 修文档）

**现象**：同一道 `regression` 闸门在**真文档**上报了 1 处——

```
L63 /立面.{0,14}65\s*%/
  | 立面的玻璃带占 65% 高度 | 腰壁做高了，从 20° 俯角看，每厘米腰壁吃掉 2.7 厘米室内 | 五 · ㉔ |
```

**现场**：这是 §1「反向推导表」的摘要行。正文 ㉔ 已经改成正确规则（"窗下墙体 ≤ 0.65 m，长度不是比例"），但**摘要表的第一列仍是旧的错误转录**。旁边两列都没有"错/编"字样，所以豁免不生效——判据正确地抓住了它。

**修的是什么**：**文档**。改为——

```
| **腰壁（窗下墙体）压到 0.65 m 以内**（长度，不是比例） | 腰壁做高了，从约 20° 俯角看，每厘米腰壁吃掉 2.7 厘米室内 | 五 · ㉔ |
```

**教训**：**摘要表 / 推文 / 精简版是旧错复活率最高的地方**，因为改完正文后人的注意力已经用完了。这也是为什么 `regression` 必须扫全文，不能只扫代码块。

> 同一次核查确认了旁边的 `2.7 cm` 是对的（源码注释 + 几何核对 `1/tan(20.3°) = 2.7`），所以只改了这一格。**判据报一处就查一处，不要顺手改对的。**

## 案例五 · 反证没生效，假通过（方法论错 → 加验证）

**现象**：第一次反证实验"注入错误后检查器报 PASS"，看着像检查器有效。

**实际**：替换串在文档里根本不存在，文件未被修改，PASS 是**正确的**。

**修的是什么**：流程。反证必须先**验证变异真的生效**（例：`assert t.count(old)==1` 后检查 `old not in t2`），再解读结果。否则会把"没改动的文件通过检查"误读成"检查器抓到了改动"。

**教训**：**反证的第一步是证明你确实制造了犯罪现场。**

# 第二批：r20 三通道外部评审实证（2026-10-12）

> 这一批的性质和前五例不同：前五例是**我们自己发现的**，这一批是**三通道评审提出、
> 我们逐条用变异实证确认后才改的**。十条断言全部证实，无一落空。
> 评审通道：kimi-k3（118.8s）/ gpt-6-astra（112.5s）/ codex-auto-review（53.4s），
> 三通道互不可见，manifest 记录实际应答模型。

## 案例六 · 豁免词是裸子串，四个自然措辞就能绕过（检查器错 → 修检查器）

**现象**：regression 的"订正上下文豁免"能被**不需要故意**的写法绕过。

**实证**（四种写法在旧版下全部 `VERDICT: PASS`）：

| 写法 | 为什么被豁免 |
|---|---|
| `玻璃带占立面总高的 65%，这个结论没错。` | 含单字 `错` |
| `与编号 ㉔ 一致：立面占 65% 高度。` | 含单字 `编` |
| `二者的区别在于立面占 65% 高度。` | 含单字 `别` |
| `立面占 65% 高度，不能调整。` | 含 `不能` |

**根因**：`DEFAULT_FIX` 里有 `错/编/别/不能/误` 这类单字。它们在**订正句**里是标记，在**断言句**里同样自然——等于在断言句最可能的措辞上开了洞。

**修的是什么**：检查器。豁免标记从裸子串改成**多字正则表**（`错误|错了|编造|编的|笔误|勘误|更正|推翻|废弃|不再适用|曾经|栽过|打回|评审|原\s*v\d|⚠`…），单字一律不作数。

**代价（有意取的偏保守）**：`旧版写法是 65%` 这种不含多字标记的正当引用会误报。**漏报比误报危险**，且误报可用 `--fix` 显式消。

## 案例七 · 非 text 围栏块被删后根本不检查（检查器错 → 修检查器）

**现象**：

```python
x = "立面占 65% 高度"   # 旧错藏在 python 块里
```

`VERDICT: PASS`。

**根因**：gate B 用 `re.sub(r'```(?:\w*)\n.*?```', '@@PASTE@@', txt)` 把**所有**围栏块替换成占位符，而 gate A 只查 `lang in ('', 'text')` 的块。语言标签非白名单的块**两头都不查**，静默消失。

**修的是什么**：检查器。gate A 改为**逐个查所有围栏块**（不论语言标签，单独报告标签），gate B 查去块后的正文。三面合起来覆盖全文、互不重叠。

## 案例八 · 断言折行即逃（检查器错 → 修检查器）

**现象**：

```
立面玻璃带占
总高的 65%。
```

`VERDICT: PASS`。

**根因**：regression 逐行 `re.search(pat, ln)`，正则天然跨不了行。而**编辑器自动折行就会无意造成这个形态**——不是攻击，是日常。

**修的是什么**：检查器。新增跨行补查：相邻两行拼接后再匹配一次；单行已处理过的跳过（避免重复计数）。

## 案例九 · 退出码契约是破的（检查器错 → 修检查器）

**现象**：文档承诺"用法/文件错误退出码 2"，实测 `check_prompt.py numbering /nonexistent.md --clauses 10` **rc=1**。

**根因**：`sys.exit('读不到文件：...')` 会把字符串写进 stderr 并**以 1 退出**。于是"路径打错"和"文档真有错"无法区分——直接违背自家硬规则 1。

**修的是什么**：检查器。所有用法/文件/参数错误统一走 `_err()` → 打印到 stderr 并 `return 2`。同时补了 `--clauses < 1`、`--sections < 0`、`--fix-window < 0`、索引越界、`--bad` 正则无法编译五类参数校验。已由 `selftest` 锁定。

## 案例十 · 数字条款语法文档承诺了但没实现（检查器错 → 修检查器）

**现象**：SKILL.md 写"支持 `1. ` 阿拉伯数字"，实测三条款文档报 `条款定义点：0 个`。

**根因**：正则 `^(\d+)[\s\u3000]` 要求数字后**直接**接空白，`1. 条款` 数字后面是 `.`，不匹配。等于告诉用户"超 50 条请走另一条路"，而那条路是断的。

**连带**：第 0 列的普通数字正文（`9 盏点光从顶部投射。`、`2026 年修订过一次。`）仍被吞成条款 9 和 2026——案例一只修掉了缩进子项，没修掉顶格正文数字。

**修的是什么**：检查器。
- 语法放宽为 `^(\d+)[.、)）]\s` 或 `^(\d+)\s`。
- 数字 > 条款总数的行自动排除并明示（杀掉 `2026`）。
- 单个杂散数字行若**剔除后编号恰好连续**，判为正文并警告，不判失败（杀掉 `9 盏点光`，同时不放过真缺号）。

## 案例十一 · 反证文档自己的预期写错了（文档错 → 修文档）

**现象**：`gate-recipes.md` 反证一写"删掉 ㊿（第 50 条）"，同段却预期 `缺失：[77]`。

**根因**：我实际跑的反证删的是第 77 条，写文档时按记忆写了 ㊿，两边没对齐。

**修的是什么**：**文档**。反证一改为删第 6 条、预期 `缺失：[6]`，并改成 selftest 里可自动执行的形式（不再依赖一份未公开的 77 条原文）。

## 案例十二 · 豁免命中伪装成"零命中"（检查器错 → 修检查器）

**现象**：正当订正被豁免时，输出是 `✓ 块1：零命中`。用户无法区分"没找到"和"找到了但忽略"。

**根因**：`judge()` 把豁免分支和未命中分支汇到同一个 `else`。

**修的是什么**：检查器。豁免命中单独报告为 `△ N 处命中但判为订正引用` 并列出位置。**这是三通道一致强调的诊断可信度问题**——一份把"我放过了它"说成"我没看到它"的报告，比没有报告更糟。

## 案例十三 · sync 基线反证是空心夹具（方法论错 → 修夹具）

**现象**：`selftest` 首跑 18/19，唯一失败项是 `sync 基线 PASS`。

**诊断**：夹具里 `GOOD_POST` 是**另一段内容**（只有一行 ⑤），却拿去和 base 的整块比。sync 报 FAIL 是**完全正确的**——错的是我把"两份不同的东西"当成了"同一内容的两份拷贝"。

**修的是什么**：**夹具**，不是检查器。`GOOD_POST` 改为 base 块的完整拷贝。

**教训**：这是案例五的同类复发——**先证明你的犯罪现场是对的**。一条红可能意味着检查器坏，也可能意味着你的测试本身没构造对。
